Prepare independent validator candidates

A colleague can prepare three separate signing identities and test their wallet against the live network. Voting admission requires a validator-stake protocol upgrade.

Admission is not live yet. The current cluster has three fixed voting roles. Sending a cluster secret or copying Docker state to another operator would expose wallet credentials and bypass the planned membership change.

Current network

Three fixed voting roles; two approvals are needed for a mutation. Validator stake weighting is not active.

Candidate nodes

Three more identities may be prepared, but they have no votes. The planned quorum is based on assigned validator stake, not node count.

Colleague: prepare public identities

On your own computer, clone the repository, verify the pinned genesis, and create private candidate keys. Share only public-invite.json with the operator.

scplit join-testnet --url https://bokiloki.ddns.net/splitchain/ --genesis configs/testnet-genesis.json
python3 -m splitchain.validator_candidate prepare --genesis configs/testnet-genesis.json --output "$HOME/splitchain-validator-keys"
python3 -m splitchain.validator_candidate verify --genesis configs/testnet-genesis.json --invite "$HOME/splitchain-validator-keys/public-invite.json"

The keys are not active voting keys until the membership migration is implemented and verified. Keep *.pem private.
